## Публикация на GitHub Pages

Сайт — статический (готовые HTML), поэтому публикуется напрямую, без сборки на стороне GitHub.

**Первая публикация (один раз):**
1. Создайте на GitHub репозиторий с именем `ecology` (имя важно — от него зависит адрес сайта `.../ecology/` и канонические ссылки в проекте).
2. Залейте в него всё содержимое этой папки в корень репозитория (можно через веб-интерфейс «Add file → Upload files» или через git).
3. В репозитории откройте **Settings → Pages**.
4. В «Build and deployment» выберите **Source: Deploy from a branch**, Branch: **main** (или master), папка **/ (root)**. Сохраните.
5. Через 1–2 минуты сайт будет доступен по адресу **https://<ваш-логин>.github.io/ecology/**. Текущие ссылки в проекте настроены на `morgunkonstantin.github.io/ecology` — если логин другой, см. ниже.

**Обновление (каждый раз, когда присылаю новый архив):**
1. Распакуйте архив.
2. Залейте файлы в репозиторий, заменив старые (через веб: «Upload files» и подтвердить замену; через git: `git add -A && git commit -m "update" && git push`).
3. GitHub Pages обновится автоматически за 1–2 минуты.

**Если ваш логин не `morgunkonstantin` или имя репозитория не `ecology`:**
канонические адреса, sitemap, feed и ссылки в 404 указывают на `morgunkonstantin.github.io/ecology`. Сам сайт при этом откроется и заработает в любом случае (внутренние ссылки относительные). Но чтобы канонические адреса, карта сайта и RSS были правильными, замените в проекте базовый URL — скажите мне ваш логин/имя репозитория, и я пересоберу проект под него одной командой.

**Полезное:**
- `.nojekyll` в корне — обязателен, он отключает обработку Jekyll (иначе GitHub может спрятать некоторые файлы). Не удаляйте его.
- `404.html` — страница «не найдено», GitHub Pages показывает её сам.
- Папки `build/` (скрипты сборки) и `design/` (заметки) можно не заливать — они не часть сайта; но если зальёте, вреда не будет.


# ЭкоСознание

Экология как способ смотреть на реальность. Статичный сайт: 17 разделов,
27 эссе, 12 лабораторий, 5 разборов в рубрике «Что не подтвердилось»,
4 разбора понятий, глоссарий, указатель имён, карта связей и полный
указатель материалов.

Публикуется через GitHub Pages: `Settings → Pages → Deploy from a branch → main → / (root)`.
Файл `.nojekyll` отключает обработку Jekyll — он обязателен, не удалять.

```
index.html              главная

glossary.html           глоссарий
about.html              о проекте

assets/global.js        вся клиентская логика: меню, оглавление, полоса чтения
assets/site.css         доступность, контраст, фокус, печать
assets/og-image.png     картинка для соцсетей (1200×630)
assets/favicon.svg      иконка
favicon.ico             иконка для старых браузеров

feed.xml                RSS
sitemap.xml             карта для поисковиков
robots.txt              (заработает после подключения своего домена)

build/pages.json          реестр всех страниц: заголовки, описания, даты, рубрики
build/glossary-slugs.json карта «термин → якорь в глоссарии»
build/patch_pages.py      приводит все страницы к единому техстандарту
build/make_feeds.py       генерирует feed.xml, sitemap.xml, robots.txt
build/make_contents.py    пересобирает contents.html
build/make_section_lists.py блоки «Материалы раздела» на страницах разделов
build/make_termlinks.py   автолинковка понятий глоссария в текстах
```

## Как вносить правки

**Добавили новую страницу?**

1. Создать HTML-файл, скопировав структуру любого существующего.
2. Дописать запись в `build/pages.json`.
3. `python3 build/patch_pages.py` — проставит canonical, Open Graph,
   иконки, JSON-LD, `<main>`, skip-link, подключит общие CSS и JS.
4. Прогнать сборку в таком порядке:
   `make_section_lists.py` → `make_contents.py` → `patch_pages.py`
   → `make_termlinks.py` → `make_feeds.py`
5. Добавить ссылку в подвал (колонка «Материалы») и на главную,
   если материал должен попасть в блок «свежее».

Принадлежность к рубрике задаётся полем `rubric` в `pages.json`,
а не именем файла — поэтому материал можно перенести между рубриками,
не переименовывая и не переписывая ссылки.

Оба скрипта идемпотентны: их можно запускать сколько угодно раз.
Всё, что они вставляют, помечено комментарием `ECO:MANAGED` —
руками эти блоки править не нужно, они перезаписываются.

**Поменяли навигацию?** Правьте её в одном файле и переносите
скриптом — прямое редактирование 52 файлов вручную уже приводило
к рассинхрону.

## Что требует внимания

**Лаборатории — вымышленные диалоги.** У лабораторий №10–12 в подписи
явно указано, что реплики сконструированы, а позиции взяты из
опубликованных работ. У лабораторий №01–09 такой пометки пока нет;
её стоит добавить — в них тоже говорят реальные люди.

**Четыре эссе — пустые.** `essay-doughnut.html`, `essay-place-based.html`,
`essay-slow-travel.html`, `essay-biomimicry.html` содержат не свой текст,
а побайтовую копию страницы «Истина как встреча». Отличаются только
`<title>` и `<meta description>`. Пока в них не появится настоящий текст,
они помечены `noindex` в `build/pages.json` и исключены из RSS и sitemap.
Чтобы вернуть их в индекс — убрать `"noindex": true` и `"broken": true`
и перезапустить оба скрипта.

**Даты публикаций.** В подписях почти везде стоит «Май 2025» — похоже на
шаблонную заглушку. Настоящие даты стоит проставить в `build/pages.json`
(поле `date`, формат `ГГГГ-ММ-ДД`), иначе RSS показывает большинство
материалов одним днём.

**`ecolife-landing.html`** — дубликат главной, ни с чего не слинкован,
закрыт от индексации. Скорее всего его можно просто удалить.

**Шрифт основного текста.** Cormorant Garamond — дисплейная антиква
с маленьким ростом строчных; для длинных русских текстов на 1,18rem
читается мелко. Заголовкам идёт. Стоит попробовать Literata,
Source Serif 4 или PT Serif для тела текста.

**Дублирование CSS.** Около 600 КБ встроенных стилей — это копии одних
и тех же правил в 52 файлах. Следующий крупный шаг — вынести общий
слой в `assets/base.css` либо перейти на генератор (11ty), где
навигация, RSS, sitemap и указатель собираются из одного шаблона.
